# ICal版

icalによるカレンダー連携機能の設計

## 設計概要

- ical管理自体はAPIを通じて行う
- icalはユーザごとに発行するものと学年ごとに発行するものの2種類を用意する
- 存在やフォーマット等はDBで管理する
- 実データはパスをランダムにしたR2の静的ファイルとして置いておく
  - ランダムはポーリングのためにAPIを叩かずに済むようにするため
  - R2バケットはカフェメニュー用とは別にする
- 毎日深夜にlambdaのバッチ処理でdbのcreated/updated_atをもとに一部を再生成する(※eventidが変わらないように)
- icalはいくつかのフォーマットを用意する(2つ目以降は全て学年ごとの発行)
  - 個人予定を1コマづつ登録する
    - タイトルと本文(icalにあれば)のフォーマットは `{xxx}` みたいなテンプレ方式である程度カスタマイズできるようにする
  - 丸ごと学校として登録する
  - 学校がある日を時間なしで登録する
  - 学校が午後まである日を時間なしで登録する(昼飯の必要性などのため)
  - 行事予定を1件づつ時間なしで登録する

## このために変える必要のある範囲

- database定義
- apiエンドポイント定義(lib) ※発行,リスト,削除,変更(←全再生成)など
- icalのフォーマット定義(lib)
- ical関連エンドポイントの実装(api)
- バッチ処理用lambda関数
- ical関連エンドポイントのクライアント(web)
- icalの管理画面の追加(web)
- その他、必要なところ
